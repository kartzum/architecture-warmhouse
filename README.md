**Управление отоплением:**

- Система получает данные о температуре с датчиков, установленных в домах. 
- Пользователи могут просматривать текущую температуру в своих домах через веб-интерфейс.

# Задание 4. Создание и документирование API

### 1. Тип API

> Укажите, какой тип API вы будете использовать для взаимодействия микросервисов. Объясните своё решение.

**UI-взаимодействие**

UI-взаимодействие построено на базе [REST](https://en.wikipedia.org/wiki/REST).

Ключевые преимущества REST API:

Масштабируемость: REST API отлично масштабируется благодаря отсутствию сохранения состояния (statelessness), 
что снимает нагрузку с сервера.

Простота: Использование стандартных HTTP-методов (GET, POST, PUT, DELETE) делает API интуитивно понятным.

Надежность: Отсутствие необходимости сохранять состояние между запросами повышает надежность, 
поскольку нет риска потери данных о сессии на сервере.

**Взаимодействие с устройствами**

Взаимодействие с устройствами построено на базе стандартных протоколов: [MQTT](https://en.wikipedia.org/wiki/MQTT),
[RTSP](https://en.wikipedia.org/wiki/Real-Time_Streaming_Protocol).

Ключевые преимущества MQTT:

Лёгкость и эффективность: MQTT имеет минимальный заголовок сообщений, 
что снижает нагрузку на сеть и делает его идеальным для устройств с ограниченными ресурсами.

Модель «публикатор-подписчик»: Вместо прямого соединения между всеми устройствами, 
они публикуют сообщения на брокер, а другие устройства подписываются на интересующие их темы. 
Это значительно упрощает масштабирование.

Надёжность и устойчивость: Протокол поддерживает разные уровни качества обслуживания (QoS), 
гарантируя доставку сообщений.

Основные причины использования RTSP:

Универсальность и гибкость: RTSP может работать с разными транспортными протоколами (TCP, UDP) 
и кодеками (H.264, H.265).

Совместимость: RTSP является стандартом для IP-камер, обеспечивая совместимость с различными системами.

Низкая задержка: Протокол обеспечивает минимальную задержку, что критично для систем видеонаблюдения.

**Межконтейнерное-взаимодейсвие**

Межконтейнерное-взаимодейсвие реализовано на базе брокера сообщений - RabbitMQ (AMQP).

Основные преимущества:

Асинхронность: Сервис-отправитель не ждет, пока сервис-получатель обработает сообщение, что ускоряет работу системы.

Разделение (Decoupling): Сервисы не зависят от времени доступности друг друга.

Масштабируемость: Можно масштабировать систему, добавляя новые очереди и потребителей, 
или настраивать кластер из нескольких брокеров для отказоустойчивости и повышения производительности.

* [RabbitMQ](https://www.rabbitmq.com/)
* [AMQP](https://www.rabbitmq.com/docs/amqp)
* [RabbitMQ - MQTT](https://www.rabbitmq.com/docs/mqtt)
